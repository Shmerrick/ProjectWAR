## Not Bugs (investigated and explained)

| Topic | Finding |
|:---|:---|
| Land of the Dead flight master unreachable | Working as designed. `LotdService.CanRealmAccessLotd` requires the tracker to be `Paused` **with** a non-neutral owning realm; the default state is `Active`/Neutral at 0 of 500 points, earned 100 per T4 battlefront lock. So the expedition opens only after one realm wins the race, then stays open for `UnlockDurationMinutes` (30). Zone 191's taxi rows are healthy for both realms. This is indistinguishable in-game from a broken flight master, and there was previously no way to control it — hence the `.lotd` GM commands added 2026-08-30 (`status`, `unlock`, `reset`, `award`). |
| "Slow SQL" warnings at startup | Not a scaling problem. The ~2.1s query is the one-time `Item_Info` load of 88,727 rows into memory (~24µs/row) so that gameplay reads the cache rather than the database. It does not grow with player count. The genuine scaling issue was unindexed per-login lookups — see `Database/03_add_hot_path_indexes.sql`. |
| 36 public quests reported as skipped (formerly BUG-012) | The keep and fortress rows are intentionally not registered as ordinary cell-spawned `PublicQuest` objects. `LoadPublicQuests` reserves every `PQuestId` referenced by `keep_infos`, and startup then attaches the same `PQuest_Info` records to their keeps for objective packet IDs and reward-chest coordinates. All 36 keep references resolve. The old `Skipped PQs` log label was misleading and now reports that the keep-owned metadata was prepared and excluded from normal cell spawning. |
| Mythic graph reports zero component links and requirements (formerly BUG-014) | This is an unfinished parity workstream, not a failed runtime join. The selected toolkit dumps (`Londos Server v2`) contain empty `AbilityComponentXComponent` and `AbilityRequirmentBin` tables, so the imported zero counts are accurate. The translator currently parses embedded `MythicComponentData` and only reports the separate link/requirement collections; it never consumes them. The toolkit's parallel `Abilities` dataset has 29,633 compatible link rows and 651 requirement rows (all link IDs and all 558 referenced requirement IDs match the imported graph), but using those relationships requires a deliberate next-phase translator/importer design. `skipped_unknown_entries` is also an intentional filter against the runtime `abilities` source set. Track remaining semantic coverage under BUG-007 rather than treating these counters as a lookup defect. |

## Bug Reporting Guidelines

When adding a new bug, please include:
- **Summary**: A concise title.
- **Description**: Detailed steps to reproduce and expected vs. actual behavior.
- **Priority**: Low, Medium, High, or Critical.
- **Status**: Open, In Progress, Resolved, or Closed.
